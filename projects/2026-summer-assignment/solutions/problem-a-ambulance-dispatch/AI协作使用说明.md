# 协作者使用说明

本仓库已经内置 AI 协作规范。协作者不需要学习 Git 命令、背提示词或向 AI 复述工作流。

## 首次准备

- 安装 Git 和 VS Code。
- 使用能读取整个本地仓库并操作终端的 AI 编程工具。
- 登录 GitHub，并安装 GitHub CLI（`gh`，强烈推荐），让 AI 能创建和查看 PR。
- Clone 仓库后，在 VS Code 和 AI 工具中打开整个 `MCM` 文件夹，不要只打开单个 Markdown 文件。

- 在 VS Code 左侧“源代码管理”中查看更改、暂存文件、提交、同步和逐行差异。

## 协作者直接说自然语言即可

AI按意思而不是固定口令识别操作：

- “我要修改论文”“我自己改一下”“帮我开个修改分支”→ 准备 `review/*` 分支并打开正文，不代写、不提交。
- “修改完成”“我改好了”“检查一下修改”→ 只检查差异并报告，不提交。
- “提交论文”“提交修改”“改好了，发 PR”→ 检查无误后 Commit、Push 并创建 PR，不自动 Merge。

### 查看最新版变化

直接要求 AI 查看 `main` 上最新版论文相对当前本地分支的变化即可。AI必须自动读取仓库规范、获取远程信息，并按章节区分：

- main 新增、删除和改写的内容；
- 当前本地分支自己的修改；
- 数字、公式、模型、引用和结论变化；
- 是否发布了新的论文版本目录。

查看操作默认只报告，不覆盖、合并或提交本地文件。

### 修改论文

直接告诉 AI 要修改的章节、目标和依据即可。AI必须自动从 `main` 创建短期 `review/*` 分支，并完成同步检查、正文修改、预览生成、验证、Commit、Push、内容增删报告和提交到 `main` 的 PR。

AI创建 PR 后必须停止。只有仓库负责人可以审核和 Merge。

“提交论文”在当前仓库语境中表示把修改提交为 PR；如果可能指竞赛平台正式交卷，AI必须先澄清，不能自行上传。

AI 的差异报告应先概括版本升级的主线和实际收益，再用 `[+]`（新增）、`[-]`（删除）、`[~]`（实质调整）列出2至6条核心变化。同一目的的多个步骤或章节必须合并说明，不能机械照抄 Git 行差异。没有变化的模型、数值和结论用一句话概括；完整逐行差异以 PR 的 `Files changed` 页面为准。

## 正确编辑与预览

- `A题论文(vX.Y).md` 是唯一正文和预览基准，只修改这一份。
- 在 VS Code 中打开整个仓库后，使用 `Ctrl+Shift+V` 或 `Ctrl+K V` 调用自带 Markdown 预览。
- GitHub 上的最终显示效果以 PR 中这份 Markdown 的实际渲染为准。
- DOCX 由论文负责人在 Markdown 合并后统一生成和排版，协作者不要并行修改同一份 DOCX。

详细 AI 行为、冲突处理和报告格式由同目录 `AGENTS.md` 强制规定。
