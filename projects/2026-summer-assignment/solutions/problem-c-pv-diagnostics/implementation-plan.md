# C题实现准备计划

> 状态：实现前计划。本文不包含正式代码，不授权生成实验结果或论文。

## 1. 实现目标与边界

实现的唯一目标是把 `validation-contract.md` 转换成最小、可复核、可重复运行的数据—模型链路。实现不得：

- 改写 DP-C-001 或 DP-C-002；
- 在验证前指定M0、M1或M2为正式模型；
- 引入机器学习、深度学习、元启发式或不必要的优化求解器；
- 把参考示例作为任务一输入；
- 创建论文或大规模实验基础设施。

## 2. 预计实现顺序

### Step 0 — 权威与环境确认

- 冷启动读取原题衍生件、`decisions.md`、`state.md`、`model-design-report.md` 和 `validation-contract.md`。
- 按仓库规则解析项目Python解释器；工具Python不得冒充项目运行环境。
- 确认工作树，避免覆盖无关用户改动。

**进入下一步的门槛：** Accepted Decisions与验证合同无冲突，项目解释器唯一且可记录。

### Step 1 — 最小数据层

计划实现 `prepare_data.py`：

- 从原始DOCX或已核对的机器阅读接口抽取三张规范表；
- 统一百分数、小数、kWh、kWh/m²、℃、m/s；
- 生成组件参数、长格式组件日发电量和日级气象/全站总量；
- 执行100组件、15历史日、1预报日、一一对应和独立求和检查；
- 将参考示例隔离为只读核验字段。

**门槛：** 共用数据合同全部通过；失败时只修复数据层，不运行三个任务。

### Step 2 — 任务一最小实现

计划实现 `diagnose_faults.py`：

- 用单一纯函数实现官方阈值及边界；
- 在不读取参考示例的路径上产生100个主分类；
- 独立实现遮挡筛查分数和非覆盖式标志；
- 生成计数、组内比例和描述性分布；
- 最后执行参考一致性核验。

计划测试：阈值边界、未定义正偏差、参考列泄漏、计数守恒、遮挡标志不覆盖主分类。

**门槛：** 任务一成功判据全部通过，故障集合才可提供给任务三。

### Step 3 — 任务二候选比较

计划实现 `forecast_station.py`：

- 用统一接口定义M0、M1和M2；
- 对三个候选使用完全相同的15折逐日留一索引；
- 保存每折预测、误差、参数、矩阵秩、条件数、约束边界状态和第16天留一预测；
- 先运行资格门槛，再按MAE及一标准误差规则选择；
- 对入选模型全样本重拟合并计算第16天点预测、置信区间和预测区间；
- 保留Student-t主区间与小规模按日残差自助敏感性比较。

计划测试：日级隔离、模型输入列、指标公式、资格门槛、模型选择可复现、非负预测和区间嵌套。

**门槛：** 至少M0合格且选择规则能机械复现。若所有简单候选失败，停止，不自动添加复杂模型。

### Step 4 — 任务三解析排序

计划实现 `rank_repairs.py`：

- 只接收任务一故障集合；
- 按官方偏差率公式反演 `E0_i` 和 `L_i`；
- 验证偏差率重构与五项可加性条件；
- 使用稳定降序排序而非优化求解器；
- 检查第10/11名、舍入端点和敏感性名单；
- 汇总历史平均增发量，并在任务二模型确定后计算第16天补充值。

计划测试：公式反演、单位、非负损失、排序交换不变量、并列处理、合计收益加和。

**门槛：** 五项排序适用条件全部成立。任何组合约束或收益交互证据都会阻断结果生成。

### Step 5 — 最小复现入口

计划实现 `reproduce_all.py`，只负责编排：

```text
数据合同 → 任务一 → 任务二候选比较/选择 → 任务三 → 结构化结果
```

入口不得复制模型逻辑，不自动生成论文，也不触发模型目录之外的探索性实验。

**门槛：** 从清洁派生目录运行可重建全部结构化结果，且每个结果携带输入口径、单位、模型/决策标识和验证状态。

## 3. 模块接口准备

| 模块 | 最小输入 | 最小输出 | 禁止耦合 |
|---|---|---|---|
| 数据准备 | 原题/支撑数据 | 规范组件表、长表、日表 | 不产生诊断或模型结论 |
| 任务一 | 组件表、日发电量、天气 | 主分类、遮挡审查、分布 | 不读取参考标签生成分类 |

## 5. 最小依赖策略

- 优先使用项目解释器中成熟的数组、表格和统计库；只有验证合同确需且现有环境缺失时才增加依赖。
- M0/M1可用透明线性代数或成熟回归库；M2只需带简单符号约束的低维拟合，不需要通用机器学习框架。
- 任务三只需公式计算和排序，不引入整数规划或优化依赖。
- 依赖安装与运行必须使用同一 `sys.executable`，并记录到复现信息。

## 6. 实施检查点与停止条件

### Checkpoint A — 数据冻结

输出只包含经核对的规范数据和数据合同报告。若维度、单位或权威不一致，停止。

### Checkpoint B — 任务一冻结

分类与遮挡审查分离，参考列零泄漏。若参考不一致，先定位原因，不进入任务三。

### Checkpoint C — 任务二模型选择

一次性报告三个候选的误差、参数稳定性、共线性和资格状态。选择严格由合同规则产生；不以更复杂或更高训练 `R²` 为理由。

### Checkpoint D — 任务三排序

先验证五项适用条件，再排序。如果条件成立，禁止增加优化模型；若不成立，停止并判断是否需要新的Decision Proposal。

### Checkpoint E — 结果接受

结构化结果必须可由单一入口重建，数值主张只能来自实际运行。此检查点仍不创建论文，论文阶段需另行授权。

## 7. 预计验证规模

- 100×15数据合同检查；
- 任务一一次确定性分类和一次小型遮挡稳健性审查；
- 任务二最多三个低参数候选×15个留一折，加一个小规模区间敏感性；
- 任务三一次解析反演、一次排序和局部端点敏感性。

不进行随机超参数搜索、大规模蒙特卡洛、外部数据采集或算法竞赛式比较。
