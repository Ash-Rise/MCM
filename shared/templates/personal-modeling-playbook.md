# 数学建模与论文方法手册

> 角色：按需查阅的方法库，不是项目治理文件或强制 SOP。
> 权威边界：题目事实以原题/官方材料为准，项目已批准语义以 `decisions.md` 为准，治理边界以 `MCM_AI_Governance.md` 为准；本手册只提供方法建议。
> 使用方式：只读取当前任务相关章节，不因存在本手册就机械执行全部流程。

## 1. 题意、数据与模型设计

### 1.1 从权威输入开始

先回到原题、官方附件和原始数据。旧论文、旧代码、README、缓存结果只能作为待审材料，不能替代题面或 Accepted Decisions。

区分三类信息：

- **题目事实**：题面或官方数据明确给出；
- **建模假设**：为闭合模型而引入，必须说明影响范围；
- **未知/歧义**：现有材料无法确定，不用旧稿或实现细节填补。

开始建模前至少弄清：每个子问真正要求输出什么、变量与单位、可用数据、决策变量、硬约束、评价指标，以及哪些语义仍未确定。

### 1.2 选择最小充分模型

模型复杂度应由问题和证据需求驱动，而不是由“算法更高级”驱动。简单模型已经能回答题目时，不主动叠加多指标算法、元启发式、复杂预测器或二次优化层。

存在多个真实可行的模型族且理论上难以区分时，先比较它们对题意的匹配、假设成本、可解释性、数据需求和结论敏感性；必要时再做最小共同 pilot。不存在真实分歧时，不为了形式制造 2—3 个候选方案。

优先使用成熟稳定的数学/数值工具；只有当现有工具不匹配问题、引入依赖反而增加不透明性，或核心方法本身就是研究对象时才自行实现。

### 1.3 先解释语义，再写公式

每个核心模型应先用自然语言回答：对象是什么、决策是什么、约束是什么、目标是什么、输出如何解释。随后再给符号、公式和算法。

数值网格、离散采样点、求解器容差、随机种子等实现参数不能自动晋升为数学定义。连续变量用有限节点计算时，应明确“定义域”和“数值采样”的区别。

## 2. 实验、仿真与证据

### 2.1 证据必须能改变决策或支撑主张

增加研究、参数扫描、仿真复制、敏感性分析或额外模型前，先问：新增证据可能改变哪个重要判断？最小可信实验是什么？若进一步计算大概率不会改变行动，就停止。

敏感性分析优先寻找参数阈值、结论翻转点和可行域边界，说明结论在什么条件下保持或失效；不以机械百分比扰动代替真正影响结论的边界证据。

正式大规模计算前先运行足够真实的小规模链路，确认模型含义、输入输出、统计口径和执行路径均可用。只有发现性能确实阻碍正式实验时才 profile 和优化。

### 2.2 随机实验

复制次数、warm-up、采样节点和置信区间方法由问题精度与模型结构决定，不使用固定数字作为跨项目规则。

比较策略时，如随机环境允许，优先采用共同随机数或其他配对设计降低比较方差；报告时说明比较对象、样本量和不确定性口径。

长计算应在合理粒度保存有效进度，使中断后无需从零开始。具体使用批次、checkpoint、增量结果或任务队列由实现决定。

### 2.3 证据冲突处理

数值、统计口径或论文描述冲突时，按证据链向上追溯：

1. 找到最原始的观测或复制级结果，确认单位、样本量和筛选条件；
2. 写清统计量、指标或置信区间的定义；
3. 使用独立路径重算最关键结果；
4. 再与汇总表、图和论文正文逐层比较；
5. 原始证据不足时保持“未知”，不以两份派生文档相互一致作为证明。

审查结论可使用三种证据状态：

- **已验证事实**：直接回到原始数据、代码、公式、文献原文或文档实际结构核验；
- **合理推断**：证据支持但依赖明确假设；
- **未知**：材料不足，不能补成确定结论。

## 3. 编程与数值实现

优先保证实现可读、可检查、可复现，再追求抽象或性能。避免为了 DRY/SOLID 等标签提前制造抽象层；少量重复通常比错误抽象更便宜。

模块按稳定职责划分；只有当数据格式或接口确实被多个下游消费者依赖时才建立稳定 schema/contract。临时中间结果不需要统一元数据体系。

优化遵循：正确的小规模链路 → profile → 优化真实瓶颈 → 复验结果一致性。不要凭直觉重写大段代码来“提速”。

自动测试优先保护稳定、重要、可机械检查的不变量，例如题目硬约束、模型定义域、守恒关系、统计分母、跨午夜状态等。一次性 bug 不自动变成永久测试；是否保留取决于该 failure class 是否稳定且后果重要。

## 4. 论文内容组织

论文结构服务于证据链，不要求所有题目机械套同一目录。一个常用基线是：

```text
问题重述
问题分析
模型假设与符号
任务一：问题 → 模型 → 算法 → 结果 → 验证/边界
任务二：...
任务三：...
模型评价
参考文献
附录
```

问题分析应明确每个子问的输入、决策、目标和约束，并说明子问之间继承的数据、模型结构或结论，使题意到模型的转化及任务依赖可追踪。

每个任务至少形成一个完整闭环：回答什么问题、为什么采用该模型、核心变量/目标/约束、算法如何得到结果、关键数值和单位、结果是否稳定/显著/可行、不能推出什么。

### 4.1 论文完整度

“完成所有子问”不等于“论文已经充分完成”。完整度取决于论证与证据链是否足以让第三方理解模型选择、计算过程、结论强度和适用边界，而不是只看是否给出了最终答案、通过了数值验证或成功生成了文档。

当赛事规则允许时，完整数学建模论文通常以约 25 页、约 15000 中文字符的实质内容作为默认完整度参考。这是诊断“是否展开充分”的软目标，不是最低篇幅配额；官方页数、字数和格式限制始终优先。明显低于该范围时，应先检查是否遗漏真正有价值的论证，而不是直接认定短论文已经完成。题目规模确实很小且证据链已经完整时，论文可以自然短于参考范围。

完整度检查至少关注是否缺少：

- 从题意到模型的推导和模型选择理由；
- 关键假设及其对结论的影响；
- 变量、目标与约束的现实解释；
- 当前算法或求解方法为何适合问题规模；
- 支撑最优性、可行性、比较或预测结论的关键中间证据；
- 真正可能改变结论的敏感性或稳健性分析；
- 异常、反直觉或零效应结果的机制解释；
- 模型限制、适用边界和可行的推广方向。

不得用通用背景、重复结论、装饰性模型或算法、没有决策价值的敏感性分析、放大图表、调整字号行距等 padding 追逐参考篇幅。内部 `题目分析报告`、实验分析或其他工作文档中已经形成、且对第三方理解模型选择或结果有实质价值的推理，应在写论文时转写成面向读者的论证，而不是只保留最终结论；不要把 Governance、Decision Proposal 等内部流程术语搬进论文。

### 4.2 摘要

摘要优先按题目任务组织，而不是压缩成一段通用技术报告。先用一两句交代研究对象、核心困难或总体方法；随后按子问题顺序高度压缩“针对该问建立或采用什么模型/方法，得到什么最关键结果”；结尾再给整体结论、真正关键的稳健性结果或适用边界。关键结果尽量带数字和单位，使读者不看正文也能知道每一问怎么做、得到什么。

摘要不展开变量定义、实现细节、验证流程、治理过程或长篇背景，也不加入正文与结果证据无法追溯的数字。通常不需要显示公式；具体段落和句数由题目结构决定，不设固定模板。

### 4.3 结果与结论

结果段先报告直接证据，再解释其含义。显著性、因果关系、最优性、鲁棒性等词必须与实际证据强度一致。候选筛选、插值、启发式和样本外比较分别按其真实地位描述，不用“全局最优”“严格证明”等更强措辞替代。

小型有限候选集若声称精确最优，应优先展示完整候选证据；若结论表现为零效应，应展示受影响集合、被删除集合与最优集合的关系，而不只报告最优值未变。

### 4.4 附录

遵循“正文可读、仓库可复现”。论文保留关键伪代码、必要公式、核心函数说明和复现入口；完整源码、测试与大体量结果由仓库或独立附件承载。

## 5. 写作语体

正文应具体、自然、由本题证据驱动。若环境已配置专门的“去 AI 味”写作 Skill，润色时优先调用该 Skill；本手册只保留以下底线：

- 少用可替换到任何论文里的套话、机械过渡和泛化评价，直接写本题对象、变量、数据、因果关系与限制。
- 不为“完整感”机械堆小标题、列表、三段式或优缺点模板；真实存在结构时再使用。
- 若删掉一句话后事实、推理或边界没有损失，通常应删掉或改得更具体。
- 去 AI 味不能牺牲严谨性；不得为了“像人写”故意加入语病、口语化、情绪化表达，或改变数字、模型名、结论方向和引文事实。
- 公式出现前先说明现实含义；结果优先报告可核验的数值与机制，不用“显著提升”“具有重要意义”等空评价代替证据。

## 6. 图与表

### 6.1 选图原则

每张图应承担一个明确的证据任务。先问“读者看完这张图应该得到哪条主要结论”，再选图型。

论文完成前，应按核心子问题检查证据覆盖：输入或空间结构、算法或作用机制、主要结果比较、时间演化或敏感性、稳健性或不确定性、反直觉或零效应机制中，是否存在适合视觉表达且能实质增加理解的 evidence view。若重要机制只能靠长段文字理解，应优先设计一张承担该证据任务的图；若表格或文字更清楚，则不为数量作图。图与表不得重复表达同一证据来充数，也不设跨项目固定图数。

常见匹配：

- 空间分布/连接关系 → 地图或网络图；
- 时间/连续参数响应 → 折线或响应曲线，可配置信带；
- 多节点差异与不确定性 → 点区间图/森林图；
- 组成结构 → 堆叠条形图；
- 精确数值比较 → 表格通常比装饰性图更好。

同一证据不要同时用表、柱状图和热力图重复表达。绝对曲线几乎重合但差值重要时，增加差值/区间视图，而不是强行夸大纵轴差异。

### 6.2 科研图视觉基线

按最终 Word 插入尺寸设计，避免生成后大幅缩小。优先矢量格式或 300 dpi 以上 PNG；颜色同时配合线型、点型或形状做冗余编码，并检查灰度可读性。图注承担统计口径、样本量、CI 类型等信息，图内只保留必要标签。

### 6.3 表格

三线表默认无竖线，列宽按语义分配。文本说明通常左对齐，方案/数值列居中或按小数点组织。先调整列宽、单元格边距和措辞，再缩小字号。

人工在 Word/WPS 中已经审核通过的表格，其布局优先于通用表格规则。内容未变时尽量保留其完整布局；内容变化时重新审核，不用旧表的布局锁定掩盖新内容问题。

## 7. Markdown、Word 与排版

论文内容与版式分阶段处理：`paper.md` 是正文内容权威；用户审核通过的 `paper.docx` 是人工版式权威。DOCX 排版工具不得静默改写已批准正文，反之 Word 手工版式也不能重新定义模型或数值证据。

精确字体、字号、行距、页边距、页码和普通三线表等跨项目机器配置统一读取 `personal-paper-profile.yaml`，不要在 playbook、项目脚本或测试中复制数值。官方规范、用户提供的当届模板或用户批准的 Word 基线对其所属版式范围具有更高优先级。

### 7.1 Markdown → DOCX

优先保持单一可编辑 Markdown 正文源。公式使用稳定的 Pandoc 数学语法，输出后检查 OMML 结构；图片路径、题注、交叉引用和表格应以最终 DOCX 的实际结果为准，而不是只看 Markdown 预览。

内容修改先回到 Markdown；内容已审核后再进入 DOCX 装配。若排版阶段发现真实内容问题，退回内容源修正，而不是直接在自动生成链中偷偷改文字。

### 7.2 人工 Word 基线

用户在 Word/WPS 中明确调整并认可的版式是后续布局工作的基线。优先提取或局部复用已批准结构，不反复凭感觉猜行距、列宽或分页参数。

对锁定表格、公式、分页等局部对象，必要时采用针对性的 OOXML 修改，避免全量重写文档导致无关布局漂移。任何自动处理后的 DOCX 都应结合结构检查和实际渲染检查受影响页面。

### 7.3 视觉 QA

结构检查回答“对象是什么、属于哪里”；实际 Word/WPS 或逐页渲染回答“页面上看起来怎样”。二者不能互相替代。

重点检查：公式缺字/竖排、正文意外居中、表头孤立、表格换行与列宽、图片裁切、题注绑定、参考文献、附录和异常大片空白。开发阶段只复验受影响页面；完整逐页检查留到正式交付。
